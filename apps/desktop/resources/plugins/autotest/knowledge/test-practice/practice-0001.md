# 用例编写规则（本团队）

Tags: 用例, 规范, 编写, 断言, 优先级

Source: standard 内部测试规范 v2.1

Id: practice-0001
Collection: test-practice

1. 一个用例只验证一个行为。同时验证多项时，失败信息无法定位责任方。
2. 预期结果必须可观测：写「返回 0x62 F1 90 加 17 字节数据」，不写「工作正常」。
3. P0 仅用于数据丢失、安全、法规路径。怠速波动、界面文案属于 P2/P3。
4. 前置条件必须显式：ECU 上电状态、会话状态、钥匙位置、之前用例的残留。
5. 边界值优先于等价类：上限、上限+1、下限、下限-1，比「正常值」更容易发现缺陷。
6. 每条用例的步骤必须可被一个脚本完整执行；需要人工介入的步骤（插拔线束、旋转钥匙）写进前置条件，不写进步骤。
